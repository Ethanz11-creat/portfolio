## 一句话方法论

**不要直接让 AI 写代码。** 先澄清需求，再给出方案、编写计划，分阶段执行，最后用测试与验收标准证明结果正确。

## 为什么不能直接让 AI 写

一句话把任务交给 AI，产出的是"看起来对"的代码：没有需求澄清，边界靠猜；没有方案评审，架构随缘；没有验收标准，正确性无法证明。流程化的输入，换来的是可验证的输出。

## SOP 五步

1. **澄清**：把模糊需求问清楚，明确边界与成功标准
2. **方案**：让 AI 给出 2-3 种方案与权衡，选定后写设计
3. **计划**：把设计拆成可独立验收的任务，每个任务有测试
4. **分阶段执行**：一个任务一个任务做，每步验证
5. **验收**：用测试与验收标准证明结果正确，而不是"看起来没问题"

## 实验框架

这套 SOP 的价值可以用对照实验验证：同一任务，一组"一句话交给 AI"，一组"按 SOP 流程化输入"，对比完成时间、返工次数与验收通过率。目标是形成可在团队内推广、且有数据论证的流程。

## 实践体会

- 澄清阶段花的时间，会在执行阶段十倍省回来
- 验收标准写不清楚，说明需求还没想清楚
- SOP 不是束缚，是把"碰运气"变成"可预期"

## 支撑这套流程的仓库

这套 SOP 不是原创方法论，而是把社区最成熟的工程技能装进了流程里。核心是 **Superpowers**：

- [obra/superpowers](https://github.com/obra/superpowers)：Claude Code 的著名方法论插件，内置从澄清到交付的完整技能链——`using-superpowers`（技能发现）、`brainstorming`（澄清需求）、`writing-plans`（写计划）、`executing-plans`（分阶段执行）、`test-driven-development`、`verification-before-completion`（验证后再宣称完成）、`requesting-code-review` 等。上面每一步其实都是它的一个 skill。
- 配套的 [obra/superpowers-marketplace](https://github.com/obra/superpowers-marketplace) 是官方插件市场，安装后在 Claude Code 里 `/plugin marketplace add obra/superpowers-marketplace`，再 `/plugin install superpowers@superpowers-marketplace` 就能用。
- 社区可编辑的 [obra/superpowers-skills](https://github.com/obra/superpowers-skills) 允许你 fork 后给这套技能库提新 skill 或改进。

一句话：**流程化输入 = Superpowers 的方法论 + 你的项目上下文**。它把"澄清 → 方案 → 计划 → 执行 → 验收"每一步固化成可复用的技能，这正是这套 SOP 能"可预期"的原因。
